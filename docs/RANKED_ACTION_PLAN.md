# Arc — Ranked Pre-Deploy Action Plan

Status: **NO-GO until the objective gate is green and the ruthless panel clears the agreed thresholds.**

Ranking principle: teacher workflow impact first, then trust/accessibility, then engineering hygiene, then polish. A lower-ranked item does not jump the queue because it is easier or prettier.

## P0 — Deployment blockers

1. **Get the full rendered browser matrix to 100% pass**
   - Fix the remaining returning-tutorial preservation test.
   - Fix the remaining color-scheme reload contract.
   - Fix the remaining Lesson→Unit context assertion.
   - Re-run all viewport/accessibility projects.
   - No deployment while any required rendered check is red.

2. **Protect teacher work and identity**
   - Commit an exact dependency lock generated by a green CI install.
   - Preserve local owner isolation.
   - Prove hard-reload persistence for plans, preferences, tutorial state, and school/calendar setup.
   - Keep cloud sync/login claims disabled until real provider-backed persistence is verified.

3. **Complete non-drag accessibility for core planning**
   - Week, Month, Quarter: every move/copy/paste/nest/delete workflow must have a keyboard path.
   - Add visible focus treatment and useful accessible names to structural controls.
   - Keep Enter/Space target selection consistent.
   - Preserve Undo as recovery for destructive actions.

4. **Make accessibility behavior a first-class preference instead of a hidden test condition**
   - Respect `prefers-reduced-motion` everywhere.
   - Ensure forced-colors/high-contrast mode preserves selection, hierarchy, and focus.
   - Add an optional in-app “Reduce motion” preference only if it adds value beyond the OS setting.
   - Add an optional “Increase interface contrast” preference if native forced-colors alone is insufficient.
   - Verify 200% zoom with no document-level overflow and usable internal scrolling.

5. **Finish schedule truth**
   - Expose real weekday and rotating/A-B meeting patterns in onboarding/setup using the existing scheduling engine.
   - Shift/Tack/Extend/Copy-next must all use the same meeting-pattern source.
   - Never invent school-calendar data.

## P1 — Core teacher workflow quality

6. **Finish the tutorial as implementation training, not a slideshow**
   - First-run eight-step walkthrough.
   - Returning-user “Review Arc tutorial.”
   - Preserve setup and plans when reopening/skipping.
   - Include keyboard/non-drag guidance where drag is optional.
   - Teach Fridge → Unit/Lesson → calendar → Shift → Day → Undo/Save in the actual product vocabulary.

7. **Strengthen Day as a true teach-from-it surface**
   - Active Unit context.
   - Today’s Lesson(s), resources, notes, fixed-date status.
   - Taught state and short “what changed?” reflection.
   - Next Lesson.
   - Multiple classes without turning the screen into cards-within-cards.

8. **Strengthen Year/Quarter planning without duplication**
   - Each school-year month appears once.
   - Quarter boundaries change color on actual configured dates.
   - Preserve yellow elapsed-day X treatment.
   - Full-year planning remains overview-first, not a dense micro-calendar.

9. **Finish Fridge/MSC interoperability**
   - Idea, Note, Lesson, Unit are one canonical loose-object model.
   - Drag and non-drag paths into calendar and Must/Should/Could.
   - No duplicate Ideas system.
   - Trash remains recoverable through Undo.

10. **Complete Month/Quarter structural operations**
    - Unit tree copy/cut/paste.
    - Selected Lesson movement.
    - Unit nesting/re-parenting where valid.
    - No arbitrary item clipping.

## P2 — Trust, resilience, and engineering hygiene

11. **Remove remaining layered/superseded code**
    - One workspace stylesheet authority.
    - Delete obsolete components instead of leaving dormant variants.
    - Architecture tests should fail if retired layers return.
    - Remove stale “Ideas” migration paths once migration is complete.

12. **Remove all build warnings we control**
    - Fix CSS/autoprefixer warnings.
    - Investigate large serialized CSS strings/assets.
    - Keep CI warning-free where practical.

13. **Resolve dependency vulnerabilities deliberately**
    - Inspect each advisory.
    - Prefer minimal non-breaking upgrades.
    - Never run blind `npm audit fix --force` on the active product branch.

14. **Visible account state only when authentic**
    - Google login only when Supabase + provider configuration is real.
    - Add visible account/sign-out once authentication is active.
    - Two-account isolation must remain proven.

15. **School calendar import/lookup**
    - District/school/city-state lookup.
    - Uploaded calendar extraction.
    - Preview and confirm before changing canonical dates.
    - Manual entry remains available and authoritative when automation is unavailable.

## P3 — Visual/product polish after workflow truth

16. **Screenshot-level ruthless design audit**
    - Day / Week / Month / Quarter / Semester / Year.
    - Fridge open/closed.
    - Shift states.
    - MSC collapsed/expanded.
    - Magnet editor.
    - Onboarding/tutorial.
    - 1728, 1440, 1280, 1366, 200% zoom, high contrast.

17. **Remove vibe-coded cues**
    - No generic dashboard cards.
    - No decorative “AI SaaS” chrome.
    - No duplicate labels, helper copy, empty panels, ornamental badges, or fake data.
    - Keep calendar dominant and interactions spatial/direct.

18. **Dark/compact modes only after primary mode is excellent**
    - Do not use alternate modes to hide density/layout problems.

## Final pre-deploy gate

Objective:
- Typecheck: 100% pass.
- Unit/behavioral tests: 100% pass.
- Production build: 100% pass.
- Required rendered tests: 100% pass.
- Core scripted teacher tasks: 100% success.
- Overall scripted interaction success: >=95%.
- Core workflows all have non-drag paths.
- Zero critical blockers and zero known repeated defects.

Simulated panel (never represented as human research):
- 15 varied teachers + 15 UI/product/accessibility experts.
- Teacher mean >=92/100; no individual <85.
- UI/product mean >=92/100; no individual <85.
- Teacher return intent >=4.6/5.
- At least 24/30 five-star ratings.

Only after these gates clear do we make a deployment decision.
