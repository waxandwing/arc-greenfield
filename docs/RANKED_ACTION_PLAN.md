# Arc — Ranked Pre-Deploy Action Plan

Status: **NO-GO until the objective gate is green and the ruthless panel clears the agreed thresholds.**

Authority: `docs/PHASE_0_BASELINE_LOCK.md` plus the Arc 2K R&D / Implementation Merge Blueprint. Ranking principle: teacher continuity impact first, then trust/accessibility, then engineering hygiene, then polish. A lower-ranked item does not jump the queue because it is easier or prettier.

## P0 — Baseline lock + deployment blockers

1. **Finish Phase 0 Baseline Lock before more feature breadth**
   - Preserve the approved Arc logo, brand work, palette family, typography roles, calendar-first shell, tactile lesson objects, and yellow elapsed-day X asset.
   - Capture visual regression evidence for the approved shell before domain migration.
   - Keep the current Unit/Fridge/clipboard/Shift behavior as parity fixtures.
   - Remove the forced first-run linear tutorial from normal product entry.
   - Replace it with the contextual **Getting to Know Arc / Explore Arc** help contract in `PHASE_0_BASELINE_LOCK.md`.
   - Do not redesign the shell while changing domain semantics.

2. **Get the full rendered browser matrix to 100% pass**
   - Correct tests that still assume the retired forced-tutorial flow.
   - Verify color-scheme reload, Lesson→Unit context, setup preservation, and contextual-help entry.
   - Re-run 1728 / 1440 / 1366 / 1280 / effective 200% / reduced-motion-high-contrast projects.
   - No deployment while any required rendered check is red.

3. **Protect teacher work and identity**
   - Commit an exact dependency lock generated by a green CI install.
   - Preserve local owner isolation.
   - Prove hard-reload persistence for plans, preferences, help state, and school/calendar setup.
   - Keep cloud sync/login claims disabled until real provider-backed persistence is verified.

4. **Begin the canonical continuity spine without a big-bang rewrite**
   - Introduce explicit `Occurrence` and `Operation` types alongside the current `Plan` model.
   - Preserve Unit and Lesson IDs and existing behavior through migration adapters.
   - Separate content identity from scheduled occurrence identity.
   - Do not duplicate lesson truth per calendar view.
   - Move consequential mutations toward command → impact preview → approval → event → projection → undo.

5. **Complete non-drag accessibility for core planning**
   - Week, Month, Quarter: every move/copy/paste/nest/delete workflow must have a keyboard path.
   - Add the documented `M` Move and `F` Park/Fridge paths once they invoke the same movement preview engine as pointer interactions.
   - Add visible focus treatment and useful accessible names to structural controls.
   - Keep Enter/Space target selection consistent.
   - Preserve Undo as recovery for destructive actions.
   - Add manual VoiceOver/Safari and NVDA/Chrome scenario evidence before release.

6. **Make accessibility behavior first-class product behavior**
   - Respect `prefers-reduced-motion` everywhere.
   - Ensure forced-colors/high-contrast mode preserves selection, hierarchy, help marks, movement preview, and focus.
   - Add explicit in-app accessibility preferences only where they add value beyond OS preferences.
   - Verify planning text/targets and 200% zoom against the R&D accessibility contract.
   - Color meaning always has a label/icon/pattern/state alternative.

7. **Finish schedule truth**
   - Expose real weekday and rotating/A-B meeting patterns in onboarding/setup using the existing scheduling engine.
   - Shift/Tack/Extend/Copy-next must all use the same meeting-pattern source.
   - Evolve that source into the canonical calendar engine rather than per-feature schedule math.
   - Never invent school-calendar data.

## P1 — Core continuity workflow

8. **Build Getting to Know Arc as contextual exploration, not a required tour**
   - After minimal setup, open the actual Arc calendar.
   - Optional invitation: `Explore Arc` / `Skip and start planning`.
   - Redistribute the existing eight tutorial explanations to first interaction with Calendar, Fridge, Unit/Lesson, Move, MSC, Shift, Day, and Undo/Save.
   - Small `?` help marks are prominent during exploration and quieter afterward; keyboard reachable and individually reopenable.
   - More → Help and guidance includes Show help marks, Show first-time explanations, Explore Arc again, Review explored features, and quick actions/keyboard help.
   - Quiet progress is allowed inside Help; no badges, confetti, streaks, mandatory completion, or giant checklist.
   - Any practice/sample content must be isolated from real teacher data and disposable.

9. **Strengthen movement trust before adding more movement controls**
   - One typed command path for drag, keyboard, menu, touch, and later API actions.
   - Impact set identifies landing, shifted, protected, displaced, skipped, unchanged, warnings, and errors.
   - Teacher sees consequences before commit when consequences exist.
   - Fridge is a first-class movement destination.
   - Undo restores the complete operation rather than one visible date.

10. **Strengthen Day as a true teach-from-it continuity surface**
   - Active Unit context.
   - Today’s occurrence(s), resources, prep, notes, fixed/protected state.
   - Planned vs taught / partial / unfinished state.
   - Short optional “what changed?” memory capture.
   - Next Lesson/occurrence.
   - Multiple classes without turning the screen into a generic card dashboard.
   - Preserve the path to Easel without embedding Easel as a second calendar.

11. **Strengthen Fridge / partial commitment**
   - Idea, Note, Lesson, Unit are one canonical loose-object family where appropriate.
   - A Lesson may belong to a Unit without belonging to a date.
   - Drag and non-drag placement into calendar and MSC.
   - Parked/displaced work keeps source context and a return path.
   - No duplicate Ideas system.
   - Trash/archive remains recoverable through Undo/restore.

12. **Complete Month/Quarter structural operations**
   - Unit tree copy/cut/paste.
   - Selected Lesson movement.
   - Unit nesting/re-parenting where valid.
   - No arbitrary item clipping.
   - Quarter remains an instructional map, not a tiny week grid.

13. **Evolve Year/Quarter teaching memory without duplicating months**
   - Each school-year month appears once.
   - Quarter boundaries change on actual configured dates.
   - Preserve yellow elapsed-day X treatment.
   - Full-year planning remains overview-first.
   - Prior-cycle notes/entry points appear only after the continuity-memory model exists.

14. **Keep Must / Should / Could contextual**
   - One collapsed/expanded strip only.
   - It allocates attention during real work; it is not a second task database.
   - Calendar/Fridge objects link rather than duplicate.
   - Red-circle importance remains distinct from crossed-out/completed state.

## P2 — Adoption, persistence, and engineering hygiene

15. **Bring the experienced teacher’s system with them**
   - Adapt onboarding around how the teacher already plans, what they already have, and what Arc should leave alone.
   - Prior-year reuse, CSV, Drive references, and Google ecosystem connections become adoption infrastructure.
   - Do not force classification or material migration merely to satisfy Arc’s data model.
   - Calibrate toward a genuinely useful first week in ≤5 minutes without a forced tutorial.

16. **School calendar import/lookup**
   - District/school/city-state lookup.
   - Uploaded calendar extraction.
   - Preview and confirm before changing canonical dates.
   - Manual entry remains available and authoritative when automation is unavailable.

17. **Move persistence from truthful-local to durable account sync**
   - Keep owner isolation.
   - Add versioned workspace persistence, durable operation history, conflict handling, and multi-tab/device strategy.
   - Save states must distinguish Saved locally / Syncing / Saved / Offline queued / Conflict / Failed.
   - No success state before durable write.

18. **Remove remaining layered/superseded code**
   - One workspace stylesheet authority.
   - Delete obsolete components instead of leaving dormant variants.
   - Architecture tests fail if retired layers return.
   - Remove stale `ideas` migration paths only after Fridge migration is proven.
   - Extract modules by responsibility; do not create another patch-stack architecture.

19. **Remove all build warnings we control**
   - Fix CSS/autoprefixer warnings.
   - Investigate large serialized CSS strings/assets.
   - Keep CI warning-free where practical.

20. **Resolve dependency vulnerabilities deliberately**
   - Inspect each advisory.
   - Prefer minimal non-breaking upgrades.
   - Never run blind `npm audit fix --force` on the active product branch.

21. **Visible account state only when authentic**
   - Google login only when Supabase + provider configuration is real.
   - Add visible account/sign-out once authentication is active.
   - Two-account isolation remains proven.

## P3 — Later vertical slices after the continuity core is trustworthy

22. **Easel round trip**
   - Arc → Easel opens the correct class/occurrence/resources/current teaching state.
   - Easel observation returns to the same lesson/day without duplicate entry.
   - Taught / partial / unfinished / no-class close states are explicit.
   - Closing Easel restores the exact prior Arc calendar range/date/selection/scroll context.

23. **Optional reflection + teaching memory**
   - Text alternative exists before voice is required.
   - Daily capture remains optional, neutral, and quick.
   - Unit / Day / Week / Next-cycle memory are distinct objects/timescales.
   - Voice/transcription remains proposal → teacher review → approval, never hidden mutation.
   - No compliance prompts, streaks, sentiment scoring, or evaluation language.

24. **Contextual adaptation / AI only after concrete teacher context exists**
   - Adapt before generate.
   - Show assumptions, time/material cost, scope, and source/provenance.
   - At most two contextual proposals compete for attention.
   - `Keep as planned` / `Save note only` remain ordinary exits.
   - No large Ask-AI destination.

## P4 — Visual/product polish after workflow truth

25. **Screenshot-level ruthless design audit**
   - Day / Week / Month / Quarter / Year and any remaining Semester decision.
   - Fridge open/closed.
   - Shift/movement preview states.
   - MSC collapsed/expanded.
   - Magnet editor.
   - Onboarding + contextual help states.
   - 1728, 1440, 1366, 1280, 200% zoom, high contrast.
   - Compare against the locked Arc brand/shell baseline, not generic SaaS references.

26. **Remove vibe-coded cues**
   - No generic dashboard cards.
   - No decorative AI SaaS chrome.
   - No duplicate labels, helper-copy walls, empty panels, ornamental badges, fake data, or toast-only promises.
   - Keep calendar dominant and interactions spatial/direct.

27. **Dark/compact modes only after primary mode is excellent**
   - Do not use alternate modes to hide density/layout problems.

## Final pre-deploy gate

Objective:
- Typecheck: 100% pass.
- Unit/behavioral tests: 100% pass.
- Production build: 100% pass.
- Required rendered tests: 100% pass.
- Core scripted teacher continuity tasks: 100% success.
- Overall scripted interaction success: >=95%.
- Core workflows all have non-drag paths.
- Movement input-method parity proven against the same command/impact result.
- Zero critical blockers and zero known repeated defects.
- Exact Arc visual baseline passes regression review.

Simulated panel (never represented as human research):
- 15 varied teachers + 15 UI/product/accessibility experts.
- Teacher mean >=92/100; no individual <85.
- UI/product mean >=92/100; no individual <85.
- Teacher return intent >=4.6/5.
- At least 24/30 five-star ratings.

Human usability evidence remains distinct from the simulated panel. The R&D thresholds should be recalibrated when real teacher studies produce observed baselines.

Only after these gates clear do we make a deployment decision.
