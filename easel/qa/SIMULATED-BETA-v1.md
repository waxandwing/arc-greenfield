# Easel hostile beta simulation v1

This is a structured persona simulation, not a claim that 30 real teachers tested this build.

## Overall simulated result
- Task-success estimate: 74%
- Confidence after first session: 3.7/5
- Likely five-star rating: 8/30
- Release blockers: 3
- Major issues: 7

## Highest-confidence wins
1. Teachers understand persistent directions quickly.
2. Timer + cleanup + phase navigation feel classroom-native.
3. Media stage concept reduces tab switching.
4. Plan as the private home for roster/pass information is understandable once visually separated.
5. Art/studio personas particularly value cleanup, materials, noise level, and persistent directions.

## Repeated simulated failure points
1. At constrained/zoomed viewports, teachers lose the lesson surface below shell chrome.
2. Class/lesson context drift is trust-destroying; local hardening now binds a board to class, but this must clear live tests.
3. First-use help competes with the interface when highlight marks cover controls.
4. Teachers are unsure whether changing a class changes the projected lesson until the relationship is explicit.
5. Too many customization concepts appear too early for reluctant-tech users.
6. Teachers expect Escape and a visible X to dismiss every temporary layer.
7. Advanced drag behavior needs obvious click/keyboard equivalents.

## Persona split
- New teachers: like guardrails; need fewer setup choices upfront.
- Veteran teachers: value speed; reject tutorial friction quickly.
- Inclusion teachers: prioritize readable directions, predictable transitions, visual time, and privacy.
- Studio teachers: strongest fit; value materials/cleanup/noise/media combination.
- Heavy smartboard users: demand touch targets, reliable full-screen recovery, and stage controls.
- Reluctant-tech users: require a useful default with almost no configuration.
